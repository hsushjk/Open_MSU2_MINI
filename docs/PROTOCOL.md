# MSU2_MINI 通信协议

MSU2_MINI 小屏的串口/USB 协议全表。分两部分：

- **第一部分：原厂固件 V1.1** —— 由官方上位机发送侧与反编译接收侧（`cmd_dispatch` @0x250、`main_loop` @0x59A）交叉验证整理，用于理解原厂行为和给反编译仓库对照。
- **第二部分：自研固件 v1.0.0** —— 本仓库配套固件（`Open_MSU2_MINI_FW`）实际实现的协议，含资产通道、免拆自更新与诊断命令。

两套固件保持同一套 6 字节帧骨架，但**回执、资产、自更新、诊断部分完全不同**，不要混用。

## 0. 两套固件怎么区分

| 项 | 原厂 V1.1 | 自研 v1.0.0 |
| --- | --- | --- |
| 握手串 | `00 4D 53 4E 30 31`（`\0MSN01`） | `00 4D 53 4E 30 32`（`\0MSN02`） |
| USB ID | `1A86:FE0C` | `1A86:FE0D` |
| 接口 | CDC-ACM + HID（HID 声明了但无端点） | 仅 CDC-ACM 双接口 |
| 帧 | 6 字节裸帧 | 同左 |
| 收流回执 | 无 | 每帧 1 字节 `0x06`/`0x15` |
| NOR 资产 | 无公开命令 | `class 0x0A` 全套 |
| 自更新 | 无 | `class 0x0A sub 12` + `0x13`/`0x14` |
| 看门狗 | 无 | IWDG ≈1.6 s |

判版本最快的一招：发 `00 56 00 00 00 00`，自研固件回 `56 01 00 TH TL AA`；原厂固件不应答。

# 第一部分：原厂固件 V1.1

## 1. 物理层

| 项 | 值 |
| --- | --- |
| 设备类型 | USB 2.0 全速复合设备，CDC-ACM + HID |
| 接口 0（CDC 控制） | EP `0x81` 中断，64 B / 1 ms |
| 接口 1（CDC 数据） | EP `0x02` Bulk OUT、EP `0x83` Bulk IN |
| 接口 2（HID） | 64 B 报告，EP `0x04` 中断 OUT、`0x84` 中断 IN（固件未实现） |
| VID / PID | `0x1A86` / `0xFE0C` |
| 字符串 | `wch.cn` / `CH32x035` / `0123456789` |
| 波特率 | 标称 19200 8N1（对 CDC 无意义，仅用于兼容） |

USB 控制传输里的 `SET_REPORT` 被当成命令处理，这构成一条越权写入通道（见 §10 缺陷 ④）。

## 2. 帧格式

```
[class, sub, p2, p3, p4, p5]      固定 6 字节
```

- 无长度、无序号、无校验、无转义。
- 多字节量与大端；颜色 RGB565 大端。
- 固件不校验长度、不做范围检查：写了多少就按多少用。

## 3. 握手与会话

| 方向 | 内容 | 说明 |
| --- | --- | --- |
| 设备 → 主机 | `00 4D 53 4E 30 31` | 上电即发，`\0MSN01` |
| 主机 → 设备 | `00 4D 53 4E 43 4E` | `\0MSNCN`，必须回 |
| 设备 → 主机 | 原样回显该 6 字节 | 表示已进流式刷屏态（`g_main_state 0→1`） |

TIM3 以 1 kHz 打 tick；**5 秒**没有新帧就调 `reset_session` 会话复位。

## 4. class 0x00 系统

| sub | 作用 | 参数 |
| --- | --- | --- |
| `0x4D` | 握手应答 | 见上 |
| `0x30` | 配置子操作 | `p2>>5` 选子操作：0 查表 / 1 设滤波系数 `k = p3<<1` / 4 写 SRAM `0x20000140+addr`（**无边界检查**） / 5 空操作 |

## 5. class 0x02 显示

| sub | 作用 | 参数 |
| --- | --- | --- |
| `0x00` | 设坐标 | `x = (p2<<8)\|p3`，`y = (p4<<8)\|p5` |
| `0x01` | 设尺寸 | `w = (p2<<8)\|p3`，`h = (p4<<8)\|p5` |
| `0x02` | 设颜色 / 页 | `p2..p5` |
| `0x03` | 绘图操作 | `p2` = 操作码，见下 |
| `0x04` | 设填充单元 | `p2..p5` 作为最常见的 4 字节像素单元 |

`sub 0x03` 操作码：

| 操作码 | 名称 | 参数 |
| --- | --- | --- |
| `0x07` | DRAW_LOAD_ADDR | 装载地址 / 进入直写 |
| `0x08` | DRAW_DATA | `p3=1`：整段 256 B；`p3=0`：`p4` = 尾段长度 |
| `0x0A` | DRAW_DIRECTION | `p3=0/1` 设方向并重新初始化屏 |
| `0x00`–`0x06`/`0x09`/`0x0B` | 内建绘图指令 | 官方上位机未使用（纯色填充、贴图、单色图、混色图、横线等） |

## 6. class 0x03 外部 Flash

| sub | 作用 |
| --- | --- |
| `0x00` | 按 24 位地址读一页 |
| `0x01` | 写一页 |
| `0x02` | 擦除地址范围 |
| `0x03` | 写页（第二版） |

对应厂商函数 `Erase_Flash_page` / `Write_Flash_Photo_fast` / `Write_Flash_ZK`，官方上位机未使用。

## 7. class 0x04 BULK

不经 `cmd_dispatch`，由主循环直接处理：`p1` = 缓冲索引，`p2..p5` 写入 `tile[idx*4]`，**一条帧搬 4 字节**。这是原厂刷屏的核心提速手段。

## 8. class 0x08 ADC

| 帧 | 回包 |
| --- | --- |
| `08 ch 00 00 00 00` | `08 ch ?? ?? hi lo` |

`p1` = 通道号（9 = 触摸，15 = 心跳/电池），`v = (p4<<8)|p5`；上位机按 `buf[0]==0x08 and buf[1]==ch` 匹配。

## 9. 刷屏流程（官方上位机编码）

```
02 00 00 00 00 00        # 坐标 (0,0)
02 01 00 A0 00 50        # 尺寸 160 × 80
02 03 07 00 00 00        # 进直写
for 每 256 B 一段:
    02 04 b0 b1 b2 b3    # 设本段最常见的 4 字节单元
    04 idx b0 b1 b2 b3   # 最多 64 条差异像素（一条搬 4 字节）
    02 03 08 01 00 00    # 段完
02 03 08 00 00 t         # 尾段
```

- 阈值 44 条：段内差异超过 44 条就干脆全发 64 条，不值得再优化。
- 全屏 25 600 B / 256 B = **100 段**。
- 差分由主机算，设备只按 `tile[]` 搬字节。

## 10. 已知缺陷（实测 + 反编译确认）

| # | 缺陷 | 后果 |
| --- | --- | --- |
| ① | `DRAW_DATA` 的 `len=(p3<<8)\|p4` 直接当循环次数 | `len==0` 时 DMA 不启动而无限轮询，**卡死** |
| ② | 无超时、无重传 | 只有 5 秒会话超时，丢字节后整屏错位 |
| ③ | 擦除范围 16 位累加 | `P+N > 0xFFFF` 回绕，可能擦掉固件自身 |
| ④ | `SET_REPORT` → `class 0/sub 0x30/子操作 4` 写 `0x20000140+addr` | 越界写 SRAM（仅 20 KB 空间，但可写坏运行态） |
| ⑤ | 帧无校验 | 丢一字节后永久错位，不能自愈 |
| ⑥ | PA6 兼 NOR MISO 与屏 D/C | 屏命令与 flash 访问必须严格串行，任何重入都会画错 |

# 第二部分：自研固件 v1.0.0

## 11. 物理层与识别

| 项 | 值 |
| --- | --- |
| 设备类型 | USB 2.0 全速，**只声明 CDC-ACM 双接口**（原厂 HID 接口已去掉） |
| VID / PID | `0x1A86` / `0xFE0D` |
| 端点 | 接口 0 控制 EP `0x81` 中断 8 B；接口 1 数据 EP `0x02` OUT / `0x83` IN，各 64 B |
| 描述符 | bcdUSB `0x0110`，EP0 64 B；字符串 `MSU2` / `MSU2_MINI` / `MSU2M24Q3001` |
| 波特率 | 任意（CDC 忽略） |

## 12. 帧格式与裁决

```
[class, sub, b2, b3, b4, b5]      固定 6 字节，多字节量与大端
```

自研固件在原厂骨架上加了三样东西：

| 机制 | 内容 |
| --- | --- |
| 版本帧 | `class 0 sub 0x56` 查询 |
| 逐帧裁决 | 每收完一次收流，回 **1 字节**：`0x06` 像素数对上 / `0x15` 少了 |
| 重新武装问候 | 上位机每次开端口（`SET_CONTROL_LINE_STATE` 0x22）后重发 `\0MSN02` |

## 13. 握手与设备主动包

| 包 | 时机 | 内容 |
| --- | --- | --- |
| 问候 | 上电、开端口、待机期每 ~50 ms、静默 120000 轮后补发 | `00 4D 53 4E 30 32`（`\0MSN02`） |
| 裁决字节 | 每帧收流完成 | `0x06` / `0x15` |
| SysTick 自检 | 开机一次 | `77 lo hi 00 00 AA` |

主机回 `00 4D 53 4E 43 4E`（`\0MSNCN`）完成握手，设备原样回显这 6 字节并置 `connected`。

## 14. class 0x00 系统

| sub | 请求 | 回包 |
| --- | --- | --- |
| `0x4D` | `00 4D 53 4E 43 4E` | 原样回显 6 B |
| `0x56` | `00 56 00 00 00 00` | `56 MM mm TH TL AA` |

```
← 56 01 00 0A 3C AA      # v1.0.0，触摸 ADC 读数 0x0A3C
       │  │  └─┬─┘
       │  │    └ 触摸 ADC 采样值（大端）
       │  └ 次版本号（FW_VER_MINOR）
       └ 主版本号（FW_VER_MAJOR）
```

## 15. class 0x02 显示

先设起点终点，再操作。**终点排他**：`x1 - x0` 才是宽度。

| sub | 名称 | 字节 | 说明 |
| --- | --- | --- | --- |
| `0x00` | 设起点 | `b2b3 = x0`，`b4b5 = y0` | 大端 |
| `0x01` | 设终点 | `b2b3 = x1`，`b4b5 = y1` | 排他 |
| `0x02` | 设页号 | `b2 = page` | 仅记录，供多页缓冲规划 |
| `0x03` | 绘图操作 | `b2` = 操作码 | 见下 |
| `0x04` | 设填充单元 | `b2..b5` | 4 字节循环铺满 `seg[256]` |

`sub 0x03` 操作码：

| 操作码 | 名称 | 参数 | 说明 |
| --- | --- | --- | --- |
| `0x00` / `0x04` | 矩形填充 | 颜色 `= (b3<<8)\|b4` | 填充 `(x0,y0)` 到 `(x1,y1)`，宽 `x1-x0` 高 `y1-y0` |
| `0x07` | 开流 | — | `win_px = (x1-x0)*(y1-y0)`，清像素计数，屏进直写 |
| `0x08` | 送段 | — | 整个 `seg[256]` 刷进窗口 |
| `0x0C` | 原样段 | 长度 `= (b3<<8)\|b4`（≤8192） | 后续字节原样进流 |
| `0x0D` | 压缩段 | 长度同上；`b5=1` 走 RLE | RLE 见下 |
| `0x09` | 收流 | — | flush 剩余、结束直写、回 1 字节裁决 |

**RLE 编码**（`0x0D` 且 `b5=1`）：

```
[像素数, 高字节, 低字节]   每 3 字节一组
```

展开成 `count` 个相同 RGB565 像素，`count` 可跨 512 B 分段边界（展开时缓冲满就地 flush）。适合纯色背景、色块、大片同色描边。

**窗口裁决**：像素数按字节折算 `frame_px += 段长/2`；收流时 `frame_px == win_px` 回 `0x06`，否则回 `0x15`，主机整帧重发。

## 16. class 0x04 段内 BULK

| 帧 | 作用 |
| --- | --- |
| `04 idx b0 b1 b2 b3` | `seg[idx*4 .. idx*4+3] = b0..b3`（仅当 `idx*4+4 <= 256`） |

与原厂同一思路：一条帧 4 字节，主机用最少字节填满 256 B 段再一次性 `02 03 08` 发出。

## 17. class 0x08 ADC / 触摸

| 帧 | 回包 |
| --- | --- |
| `08 ch 00 00 00 00` | `08 ch 00 00 hi lo` |

`ch 9` = 触摸电极（TKey 注入通道：`CTLR1 |= 1<<24`、`IDATAR1=0x70`、`RDATAR=0x40`，等 `EOC|JEOC`），`ch 15` = 心跳/参考。**与 V1.1 的差别**：回包第 3、4 字节固定填 0，只保证 `buf[0]==0x08 && buf[1]==ch` 与 `(hi<<8)\|lo` 这两点兼容。

## 18. class 0x0A 资产 / 自更新 / 诊断

这是 v1.0.0 新增的主通道，`class 0x0A`。

### 18.1 状态查询 `00` / `07`

```
→ 0A 00 00 00 00 00
← 0A 00 bv ml mh bm sm cnt dl dh fm bh 00 AA     共 14 字节
```

| 序号 | 字段 | 含义 |
| --- | --- | --- |
| [0] | `0A` | class |
| [1] | sub | 原样回 |
| [2] | `boot_valid` | 开机图槽是否有效（1 = 有图） |
| [3][4] | `mask_lo/hi` | 16 个待机槽的有效位图（小端） |
| [5] | `boot_mode` | 0 不画 / 1 显示 NOR 图 / 2 开机自检 |
| [6] | `standby_mode` | 0 黑屏 / 1 四角方块 / 2 轮播 / 3 弹球 / 4 预留 |
| [7] | `count` | 轮播张数 |
| [8][9] | `dwell` | 每张秒数（大端） |
| [10] | `fw_major` | 主版本号（0x01） |
| [11] | `boot_hold` | 开机图停留秒数（1..60） |
| [12] | 0 | 保留 |
| [13] | `AA` | 结束标记，**必须校验** |

### 18.2 图像写入流程

```
→ 0A 01 kind slot len_hi len_lo        # kind: 0=开机图, 1=待机图
← 0A 01 06 00 00 00                    # 0x15 = 拒绝（正忙/参数非法）
→ 0A 08 00 00 wl_hi wl_lo              # 声明这一窗的长度（≤4096，0 按 4096）
→ (wl 字节数据)                        # 收满回：0A 08 06 00 00 00
   … 重复分窗 …
→ 0A 03 c0 c1 c2 c3                    # 提交 zlib.crc32(payload)，大端
← 0A 03 06 00 00 00                    # 对上才把 20 B 槽头写进去
```

任何一步失败都可以用 `0A 02 00 00 00 00` 放弃（清接收状态），回 `0A 02 06`。

### 18.3 资产通道全表

| sub | 名称 | 请求字节 | 回包 |
| --- | --- | --- | --- |
| `00` / `07` | 状态查询 | — | 14 B，见 18.1 |
| `01` | 开始写图 | `b2=kind`，`b3=slot`，`b4b5=len` | `0A 01 06/15 00 00 00` |
| `02` | 放弃本次写 | — | `0A 02 06 00 00 00` |
| `03` | 提交 CRC32 | `b2..b5 = crc32`（大端） | `0A 03 06/15 00 00 00` |
| `04` | 预览槽 | `b2=kind`，`b3=slot` | `0A 04 06/15 00 00 00` |
| `05` | 擦除槽 | `b2=kind`，`b3=slot` | `0A 05 06 00 00 00` |
| `06` | 存设置 | `b2=boot_mode`，`b3=standby_mode`，`b4=count`，`b5=dwell` | `0A 06 06 00 00 00` |
| `08` | 送一段数据 | `b4b5 = 长度` | 收满回 `0A 08 06 00 00 00` |
| `09` | 开机停留秒数 | `b2 = 1..60` | `0A 09 06 secs 00 00` |
| `0A` | 整片抹 NOR | — | `0A 0A 06 00 00 00` |
| `0B` | 开机自检结果 | — | `0A 0B rep 00 00 00` |
| `0C` | 读 NOR | `b2b3b4 = 24 位地址`，`b5 = 1..48` | `0A 0C n <n 字节> AA` |
| `0D` | 复位面包屑 | — | `0A 0D stage boots_lo boots_hi AA` |
| `0E` | 资产回读校验 | `b2=kind`，`b3=slot` | `0A 0E 06/15 crc_lo crc_hi AA` |
| `0F` | 上次自更新结果 | — | `0A 0F code 00 00 00` |
| `10` | 动画步进探针 | `b2 = 1..40` | `0A 10 06 n 00 AA` |
| `11` | 分块签名核对 | 帧后紧跟 100 B 签名 | 10 B：`0A 11 … AA`，`[2+bit]` 置位 = 该块没对上 |
| `12` | 自更新写入 | `b2=01` 开始（`b4b5=len`）/ `b2=02` 分窗（`b4b5=wl`≤2048） | 开始 `0A 12 06/15`；分窗收满 `0A 12 06` |
| `23` | 内部 flash 写序列体检 | — | `0A 23 code g_up_result 00 00` |
| `24` | 体检区读回 | — | 12 B：`0A 24 08 <0x08007000 起 8 字节> AA` |

### 18.4 设置字段与钳位

| 字段 | 取值 | 越界 |
| --- | --- | --- |
| `boot_mode` | 0 不画 / 1 显示 NOR 开机图 / 2 开机跑自检 | >2 → 0 |
| `standby_mode` | 0 黑屏 / 1 四角方块 / 2 轮播 / 3 Ping-Pong / 4 预留 | >4 → 1 |
| `count` | 轮播参与张数 | 0 或 >8 → 1 |
| `dwell` | 每张秒数 | 0 → 3 |
| `boot_hold` | 开机图停留秒数（`sub 09` 单独写） | 0 → 4 |

`sub 06` 存完会立即按新设置重画：`boot_mode==2` 画自检画面 5 行，否则走 `standby_draw()`。

### 18.5 分块签名（`sub 11`）

屏被切成 **50 块**（`16×16` 像素，5 列 × 10 行）。每帧结束主机发 100 B 签名（每块 1 个小端 u16，`sum = Σ(hi*3+b+1)`），设备逐块比较 `want != (tile_sum ^ tile_xor)`，把没对上的块写进回包掩码，主机据此只补画那几块。这是长稳运行的兜底手段：单帧裁决只看像素数，签名看的是内容。

### 18.6 NOR 读（`sub 0C`）

```
→ 0A 0C 00 08 00 10        # 地址 0x000800，读 16 字节
← 0A 0C 10 xx … xx AA      # 长度 1 字节 + 数据 + 结束标记，共 n+4 字节
```

地址 24 位（最大 0xFFFFFF），长度 1..48。

## 19. class 0x13 / 0x14 自更新

```
→ 0A 12 01 00 len_hi len_lo      # 1. 擦 NOR 0x080000，登记长度（1..48000）
← 0A 12 06 00 00 00
→ 0A 12 02 00 wl_hi wl_lo        # 2. 分窗（≤2048）
→ (数据)
← 0A 12 06 00 00 00              #    每窗收满回一次
→ 13 00 c0 c1 c2 c3              # 3. 提交 CRC32
← 13 00 06 00 00 00
→ 14 00 00 00 00 00              # 4. 置“请更新”并立即搬运
← 14 00 06 00 00 00              #    先回，再擦写内部 flash → 复位
```

失败时 `0x14` 回 `14 00 15 <g_up_result> 00 00` 并清标志；结果码：

| 值 | 含义 |
| --- | --- |
| 0 | 成功（随后自动复位） |
| 1 | 镜像头 magic 不对 |
| 2 | 长度非法（0 / >48000 / 非 256 整倍） |
| 3 | 体检失败（`0x7000` 页擦写读回不一致，内部 flash 未动） |
| 4 | 搬运后读回校验失败 |

## 20. NOR 布局与槽格式

| 地址 | 大小 | 用途 |
| --- | --- | --- |
| `0x000000` | 0x6800 | 开机图 1 槽 |
| `0x008000 + idx*0x6800` | 0x6800 × 16 | 待机图 16 槽（0..15） |
| `0x080000` | 16 B + len | 自更新镜像暂存 |
| `0x0A0000` | 4 KB | “请更新”标志扇区 |
| `0x0FF000` | 32 B | 设置区 |

槽头 20 B：`'MSA1'(4) | w(2) | h(2) | fmt(1) | flags(1) | len(4) | crc32(4) | pad(2)`，后接 25 600 B RGB565 小端像素。**数据写完才写头**，所以断电不会产生“头合法、数据半截”的槽。

## 21. 超时与保险

| 机制 | 触发 | 行为 |
| --- | --- | --- |
| 段超时 | 段内 4000 轮（约 4 s）无新字节 | 丢弃本段、结束直写 |
| 字节预算 | 一次会话 `stream_bytes > 40000` | 清空全部会话状态，重来 |
| 资产/OTA 半开窗 | 空转 4000000 轮 | `asset_abort()` / 丢弃窗口 |
| 接收环满 | `rx[1024]` 满 | 只 NAK 不覆盖，不丢字节 |
| IWDG | ≈1.6 s 没喂 | 复位（擦写循环里也喂） |

## 22. 兼容性对照

| 项 | 原厂 V1.1 | 自研 v1.0.0 |
| --- | --- | --- |
| `class 0x02` 坐标/尺寸/操作码 | 有 | 有，但终点排他（原厂用独立尺寸帧） |
| `class 0x04` 4 字节 BULK | 有 | 有，语义相同 |
| `class 0x08` ADC | 有 | 有，`buf[1]==ch`、`(hi<<8)\|lo` 兼容 |
| `class 0x00 sub 0x30` 配置/SRAM 写 | 有（有越界洞） | 不实现 |
| `class 0x03` NOR 页命令 | 有（未使用） | 不实现，改走 `0x0A sub 0C` |
| `class 0x09` 存档（devcfg） | 有 | 不实现，无应答 |
| `class 0x5A` 逐帧调试 | 无 | 早期有，v1.0.0 移除 |
| 收流回执 | 无 | 1 字节 `0x06`/`0x15` |
| 版本帧 | 无 | `sub 0x56` |
| 资产 / OTA / 诊断 | 无 | `0x0A` 全套 + `0x13`/`0x14` |

上位机侧对 `0x15` 的处理是：清编码器缓存 → 整帧重发；连续多帧无回执则重连串口。
